# 统一题目难度评价规范（difficulty-v1）

## 范围与责任

- 题目难度只反映完整主问题及追问要求的知识深度 K 和解题复杂度 C；不使用公司规模、候选人回答质量或参考答案推断难度。
- LLM 输出技术领域、知识点、细分题型、K、C 和判定理由。服务端验证 K/C 并按固定矩阵计算 L；模型不直接给 L 或最终分数。
- 非技术的个人经历、项目与行为题可标为 `NON_TECHNICAL`，仍根据题目实际要求判 K/C。领域为 `OTHER` 时展示原分类和理由，不把未知领域冒充已知技术领域。
- ASR 或角色证据不足的问题不参与分数或领域统计；历史问题无难度字段时不反填猜测等级。

## 分级定义

| 级别 | 名称 | 题目要求 |
| --- | --- | --- |
| L1 | 基础认知 | 术语、用途或单一概念 |
| L2 | 基础理解 | 基本原理、过程或简单比较 |
| L3 | 深入理解 | 底层机制、多步骤分析 |
| L4 | 综合应用 | 多知识点协同、工程场景分析 |
| L5 | 复杂设计 | 多约束设计、权衡与深度优化 |

K1～K5 分别代表基础概念、基本原理、底层机制、深入分析、架构与深度优化。

C1～C5 分别代表单一知识点、少量关联或单步推理、多步骤分析、多知识点综合应用、复杂设计与权衡。

| K / C | C1 | C2 | C3 | C4 | C5 |
| --- | --- | --- | --- | --- | --- |
| K1 | L1 | L1 | L2 | L2 | L3 |
| K2 | L1 | L2 | L2 | L3 | L3 |
| K3 | L2 | L2 | L3 | L4 | L4 |
| K4 | L2 | L3 | L4 | L4 | L5 |
| K5 | L3 | L3 | L4 | L5 | L5 |

例如，“TCP 是什么”通常为低 K、低 C；“解释三次握手的过程”为基本原理；“分析高并发下连接建立和资源优化”需要更高 K/C。具体值以实际提问和追问为准。

## 与现有模块的关系

| 处理 | 方式 |
| --- | --- |
| ASR、说话人和时间戳、问答提取、任务恢复 | 直接复用 |
| 标准答案、逐项 Rubric、关键错误 69 分上限、服务端确定性计分 | 直接复用；标准生成同时分析 K/C |
| 问题表、标准缓存、面试详情接口 | 扩展难度字段；缓存按 `rubric-v4` 隔离 |
| K/C→L 矩阵 | 新增纯业务规则 `QuestionDifficultyPolicy` |
| 技术领域和难度统计 | 从当前有效、已计分题目实时汇总；返回题数、均分及样本不足标记 |

综合面试分数继续沿用已有确定性计算，难度等级不直接变成题目权重。领域统计是补充分析，不将一道 L5 题目自动放大为多道题的权重。公司名称等面试元信息仅用于原有业务展示，不参与这套统一评分。修改规则时须更新 `difficultyRuleVersion` 和提示词版本，历史评分不静默重算。

开发库使用最新 `sql/schema.sql` 重建或在已有表上补齐新增列；仓库仅维护完整 schema 和 data，不保留分散迁移脚本。
