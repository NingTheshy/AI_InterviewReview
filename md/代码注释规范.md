# 代码注释规范

本项目使用中文 Javadoc 说明业务意图，代码本身表达实现细节。注释应随功能变更同步更新。

## 适用范围

- 核心服务、配置、客户端、过滤器、异步任务和安全边界必须有类级 Javadoc，说明职责、输入输出边界和关键约束。
- 对外接口、公共方法以及会影响数据一致性、权限、计分、重试或资源释放的方法，使用 Javadoc 写明行为、关键参数、返回值和异常语义。
- 私有方法仅在名称无法表达其业务规则、校验目的或安全原因时添加短 Javadoc。
- 行内注释只解释“为什么这样做”，例如权限校验顺序、事务边界、模型输出可信边界和内存约束；不重复代码字面含义。

## 编写要求

- 使用 `/** ... */` 书写 API 契约；公开方法在参数或返回值存在业务含义时补充 `@param`、`@return`、`@throws`。
- 使用 `//` 书写紧邻代码的决策说明，保持一条注释只描述一个原因。
- 不在注释中出现密钥、Token、真实个人数据或可复用的签名信息。
- 注释描述当前行为，不保留已废弃实现的“待修改”说明；历史兼容逻辑须明确其适用范围和替代路径。
