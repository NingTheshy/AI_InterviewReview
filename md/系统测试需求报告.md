# 面试复盘系统——系统测试需求报告

> 编制日期：2026-10-15
> 适用范围：AI InterviewReview 面试复盘系统

## 1. 引言

### 1.1 编制目的

本报告定义面试复盘系统上线前的系统测试需求、验收准则和测试范围，用于指导测试设计、执行、缺陷闭环和上线决策。测试以用户可感知的业务结果、数据正确性、安全性、稳定性和可运维性为核心，确保系统在真实面试复盘场景中可用、可靠且可追溯。

### 1.2 适用范围

本报告覆盖面向候选人或用户的面试复盘业务闭环：身份认证、个人资料、面试记录创建与管理、复盘内容录入、AI 分析/总结（如项目启用）、问题与答案管理、检索筛选、统计展示、数据导入导出、权限控制及异常处理。管理端、第三方大模型、对象存储、消息/邮件服务等外部依赖，按项目实际启用情况纳入集成测试。

### 1.3 术语

| 术语 | 说明 |
| --- | --- |
| 面试记录 | 一次面试所对应的基础信息、过程信息和结果信息的业务实体。 |
| 复盘 | 对面试表现、题目、答案、反馈、改进计划等内容的记录、分析和回顾。 |
| AI 分析 | 调用大模型或算法服务生成摘要、评分、建议、标签或问答结果的能力。 |
| P0/P1/P2 | 缺陷优先级：阻断/严重/一般。 |

## 2. 测试目标与质量门槛

### 2.1 测试目标

1. 验证核心业务流程可端到端完成，且结果可查询、可修改、可追溯。
2. 验证业务规则、数据校验、状态流转及权限隔离正确执行。
3. 验证系统在正常负载、峰值负载和依赖异常下的性能与稳定性。
4. 验证敏感个人信息、账号凭据、面试内容及 AI 请求数据得到妥善保护。
5. 验证系统可观测、可恢复，并具备上线运行所需的日志、告警和备份能力。

### 2.2 准入条件

1. 需求、原型/API 文档、数据库变更及部署说明完成评审并可追溯。
2. 测试环境与生产环境在操作系统、中间件版本、配置项和网络策略上保持可比性。
3. 构建包可部署；关键接口可访问；测试账号和脱敏测试数据准备完毕。
4. 第三方服务提供可控的测试密钥、模拟服务或明确的降级方案。

### 2.3 准出条件

1. 本报告范围内的需求测试用例执行完成率为 100%。
2. P0、P1 缺陷为 0；P2 缺陷均已修复、延期经业务负责人书面接受，或具备明确规避措施。
3. 核心业务、权限、安全、备份恢复和性能基准测试均通过。
4. 回归测试通过，未出现功能倒退；测试报告、缺陷清单和上线风险已归档。

## 3. 系统测试范围

### 3.1 功能范围与验收要求

| 编号 | 功能域 | 系统测试需求 | 验收准则 |
| --- | --- | --- | --- |
| FR-01 | 注册与登录 | 支持账号注册、登录、退出、会话续期/失效；对错误凭据、重复账号、频繁尝试进行安全处理。 | 合法用户可完成认证；非法请求不泄露账号存在性或内部错误；退出后受保护资源不可访问。 |
| FR-02 | 身份与权限 | 按角色或数据归属控制菜单、页面、接口和数据访问。 | 用户仅能查看和操作已授权数据；越权访问返回统一、可识别的拒绝结果。 |
| FR-03 | 个人资料 | 支持查看和修改允许维护的个人信息，并对格式、长度和敏感字段变更做校验。 | 保存后数据准确回显；非法输入被阻止且提示清晰；不允许修改受控字段。 |
| FR-04 | 面试记录 | 支持新建、查看、编辑、删除/归档面试记录；记录包含岗位、公司、日期、轮次、结果、备注等已配置字段。 | 必填项、时间逻辑、字段长度和枚举值校验正确；列表与详情数据一致。 |
| FR-05 | 复盘内容 | 支持录入与维护面试题、回答、表现评价、反馈、待改进项和行动计划等复盘信息。 | 新增、编辑、删除后数据正确保存；关联关系正确；取消操作不产生脏数据。 |
| FR-06 | 问题库/标签 | 支持题目分类、标签、难度或知识点等项目已启用的结构化能力。 | 标签关联、去重、筛选及统计结果正确；删除受引用数据时按规则拦截或级联处理。 |
| FR-07 | 搜索与筛选 | 支持按关键字、时间、公司、岗位、面试结果、标签等条件查询与组合筛选。 | 查询条件准确生效；空结果、特殊字符、边界日期和分页表现正确。 |
| FR-08 | 统计与看板 | 展示面试次数、结果分布、常见题目、能力短板、完成进度等项目已配置指标。 | 指标口径与明细数据一致；筛选维度变更后统计同步更新；无权限数据不参与展示。 |
| FR-09 | AI 复盘能力 | 如启用 AI，支持提交可分析内容并展示结果、状态和失败提示；可按需重新生成。 | 输入与输出正确关联；超时/限流/服务异常可感知且可重试；不可将他人数据带入上下文。 |
| FR-10 | 导入导出 | 如启用，支持按模板导入或按条件导出用户有权访问的数据。 | 模板、字段校验和错误行提示准确；导出字段、编码和权限与页面一致。 |
| FR-11 | 文件附件 | 如启用附件/音频/简历，支持上传、下载、预览和删除。 | 文件类型、大小、数量受控；越权下载被拦截；失败上传不产生孤儿文件。 |
| FR-12 | 系统提示与异常 | 所有关键操作提供明确反馈；异常统一处理。 | 成功、失败、空状态、加载中和网络异常均有可理解提示；不向前端暴露堆栈、密钥或 SQL。 |

### 3.2 端到端核心场景

1. 新用户注册/登录 → 完善资料 → 新建面试记录 → 保存复盘 → 查询详情 → 编辑 → 退出并重新登录验证数据持久化。
2. 已登录用户录入面试题与回答 → 发起 AI 分析 → 获取建议/失败状态 → 修改原始内容 → 重新分析并验证版本或覆盖规则。
3. 多用户并存 → 用户 A 创建记录 → 用户 B 使用页面、接口参数和直接 URL 尝试访问/修改/删除 → 必须被拒绝。
4. 条件筛选 → 核对列表、详情、统计数据 → 分页切换与刷新 → 数据口径保持一致。
5. 网络中断、重复提交、浏览器刷新、会话过期、服务重启等中断场景 → 验证事务一致性、幂等性和用户提示。

### 3.3 不在本轮范围内的内容

除非项目已明确交付，否则不纳入正式验收：底层大模型回答的事实正确性/价值判断、第三方平台自身 SLA、未启用的支付/社交/消息功能、仅用于开发调试的接口。上述内容可作为风险项记录。

## 4. 非功能测试需求

### 4.1 性能与容量

具体并发量应以业务预测和部署规格确认；在目标值未确认前，以下作为最低验收基线：

| 编号 | 指标 | 最低要求 |
| --- | --- | --- |
| NFR-P-01 | 页面/普通查询接口响应 | 正常负载下 P95 ≤ 2 秒，P99 ≤ 4 秒；不含第三方 AI 推理时长。 |
| NFR-P-02 | 写入操作 | 保存面试记录、复盘等 P95 ≤ 3 秒，重复提交不得产生重复记录。 |
| NFR-P-03 | AI 异步任务 | 应在页面展示排队/处理中状态；超过约定超时时间必须失败可见、可重试且不阻塞其他业务。 |
| NFR-P-04 | 并发稳定性 | 在目标并发及持续 30 分钟压测下，无服务崩溃、无明显内存持续增长、错误率 < 1%。 |
| NFR-P-05 | 容量边界 | 大文本、最大附件、最大分页、历史数据量达到设计上限时，系统应可控响应且不出现数据损坏。 |

### 4.2 安全与隐私

1. 全链路使用 HTTPS；Cookie、令牌和会话配置符合安全属性要求，令牌不得出现在 URL、日志或前端源码中。
2. 密码仅以强哈希形式保存；不得明文回传、记录或展示。登录、重置等接口需具备合理限流和防暴力破解措施。
3. 所有受保护接口必须进行服务端鉴权和对象级授权；不得仅依赖前端菜单隐藏。
4. 对输入进行服务端校验、编码或参数化处理，防御 SQL 注入、XSS、CSRF、路径遍历、文件上传绕过及常见越权攻击。
5. 面试记录、联系方式、简历、音频及 AI 提示词均按个人敏感业务数据处理：最小化收集、最小权限访问、日志脱敏、按规则删除。
6. AI 服务调用不得泄露密钥；向外部模型传输数据前，应明确数据范围、用户告知与脱敏策略，并禁止跨用户上下文串扰。

### 4.3 可靠性与可恢复性

1. 服务异常、数据库短暂不可用或第三方调用失败时，系统应返回可理解的错误提示，不得丢失已确认的数据。
2. 关键写操作应具备事务一致性；异步任务应具备状态追踪、重试限制和幂等保护。
3. 数据库备份应至少每日执行一次；上线前必须完成一次备份恢复演练，并验证记录、关联复盘和附件元数据可恢复。
4. 目标可用性建议不低于 99.5%（按月统计）；计划维护需提前告知并可回滚。

### 4.4 兼容性与易用性

1. 支持项目声明的桌面浏览器最近两个主要版本；移动端适配范围须在上线前明确。
2. 常用分辨率下不出现关键控件遮挡、页面横向溢出或无法操作的弹窗。
3. 表单标签、必填提示、错误原因、空状态和危险操作确认应清晰；键盘操作与基础可访问性应满足项目约定。
4. 中文文本、特殊字符、长文本、表情符号和换行保存、搜索、导出时不得乱码或截断。

### 4.5 可观测性与审计

1. 对登录失败、权限拒绝、关键数据增删改、AI 调用、导入导出和系统异常记录可检索审计日志。
2. 日志应包含时间、请求标识、操作者标识（脱敏）、操作结果和错误摘要；不得记录密码、完整令牌和敏感原文。
3. 应监控服务存活、错误率、接口时延、资源使用、数据库连接和 AI 调用失败率，并配置关键告警。

## 5. 数据测试需求

1. 验证所有实体的必填、唯一性、长度、格式、枚举、日期范围及关联完整性约束。
2. 验证创建、编辑、删除/归档、恢复（如支持）后的前后端和数据库数据一致性。
3. 验证并发编辑、重复点击、请求超时与重试时不会生成重复数据或破坏关联关系。
4. 仅使用脱敏或虚构的姓名、公司、邮箱、电话、简历和面试内容作为测试数据；禁止将生产个人数据直接复制至测试环境。
5. 验证时间字段的时区、排序和筛选边界，尤其是跨日、月末、闰年和未来日期限制。

## 6. 接口与集成测试需求

1. 对每个 API 验证认证、授权、请求参数、状态码、返回体、分页、排序、幂等性和错误码一致性。
2. 验证前后端字段命名、枚举值、空值表达和日期格式的一致性，避免仅 UI 正常而接口语义错误。
3. 对数据库、缓存、对象存储、AI 服务、邮件/短信等依赖，验证正常、超时、限流、认证失败、返回畸形和服务不可用场景。
4. 外部依赖失败时，业务服务应有明确超时、重试/熔断或降级策略，且不得无限等待或无限重试。

## 7. 测试方法与用例设计要求

1. 功能测试采用等价类、边界值、判定表、状态迁移和场景法；关键逻辑需覆盖正向、反向和异常分支。
2. 接口测试覆盖有效/无效 token、缺参、空值、超长、非法枚举、重复请求、跨用户资源 ID、SQL/XSS 特殊字符。
3. 性能测试至少包含基准、负载、压力和稳定性测试；压测数据不得污染正式数据。
4. 安全测试至少包括认证、授权、会话、输入验证、敏感信息泄露、上传安全与常见 Web 攻击检查；必要时配合专业安全扫描和人工复核。
5. 每个缺陷应记录环境、版本、前置条件、复现步骤、实际结果、期望结果、证据和优先级；修复后必须回归关联场景。

## 8. 缺陷分级与处置

| 级别 | 定义 | 示例 | 上线处理 |
| --- | --- | --- | --- |
| P0 阻断 | 核心服务不可用、数据严重丢失/泄露、可批量越权。 | 无法登录、任意用户可读取他人复盘、数据库写入损坏。 | 必须修复并回归。 |
| P1 严重 | 核心流程失败或错误结果影响主要用户，且无可接受替代路径。 | 无法保存复盘、AI 调用卡死影响主流程、导出越权。 | 必须修复并回归。 |
| P2 一般 | 非核心功能异常或存在临时规避方式。 | 个别筛选条件无效、提示文案错误。 | 原则上修复；延期须评审接受。 |
| P3 轻微 | 不影响业务正确性的视觉或体验问题。 | 轻微对齐、非关键文案。 | 记录并排期处理。 |

## 9. 风险、假设与待确认项

1. 本报告依据“面试复盘系统”的典型业务闭环编制。项目实际已实现模块、角色、接口字段和部署拓扑需与研发文档逐项映射，未启用功能应标记为不适用。
2. 如接入外部大模型，模型输出具有概率性；验收应侧重请求隔离、可用性、结构完整性、异常处理与内容安全，不应承诺固定措辞或绝对正确性。
3. 性能并发、数据规模、RTO/RPO、浏览器支持矩阵及合规归属须由产品、运维和业务负责人确认后写入最终版。
4. 若存在管理员、导师、企业客户等角色，应补充多租户隔离、审批流、组织权限及审计保留期限需求。
