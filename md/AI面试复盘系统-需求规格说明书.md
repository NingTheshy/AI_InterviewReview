# AI 面试复盘系统需求规格说明书（SRS）

> 文档版本：v1.2
> 编制日期：2026-10-21
> 适用范围：MVP 版本
> 文档状态：已同步面试业务闭环与公开面经要求

> **变更基线（取代旧分享和同步上传描述）：** 简历采用独立异步上传与解析；面试创建只接受有效 `resumeId`，不接受 `resumeFile`。音频限制为 MP3/WAV、2GB、2 小时。私密分享、分享 token 和一场面试多个分享链接已移除，统一为每场面试最多一篇数字 ID 公开面经。收藏仅支持问题且无总数上限。

## 1. 引言

### 1.1 编写目的

本文档对 AI 面试复盘系统 MVP 的业务范围、功能需求、数据需求、外部接口、质量属性和验收条件作出统一约定，作为系统设计、开发、测试和答辩说明的依据。

### 1.2 项目背景与目标

本系统面向个人求职者。用户提交面试录音、岗位 JD 与个人简历后，系统通过语音识别、说话人角色映射和大语言模型分析，自动识别面试问答对，形成逐题评分、整体评分、标准满分回答及改进建议，帮助用户复盘面试表现。

系统的核心目标如下：

1. 将面试音频转写为带说话人角色和句子级时间戳的可追溯文本；
2. 识别面试问题与候选人回答，并为每道题生成独立的标准满分回答和评分量表；
3. 使用固定量表与服务端确定性规则计算评分，避免由 AI 直接给出不稳定的最终数值；
4. 为用户提供历史记录、笔记、收藏、分享及公开面经浏览能力；
5. 为管理员提供用户、公开面经、评论、AI 配置与系统统计的管理能力。

### 1.3 文档依据与适用规则

本文档仅整理项目现有材料，不新增未在材料中确认的业务能力。资料的适用优先级如下：

1. `AI面试复盘系统-需求文档.md` v1.4（2026-09-21）为当前需求的首要依据；
2. 数据库、技术架构和开发文档用于补充数据约束、接口约定及实现边界；
3. `音频分片转录实现文档.md` 已标注“已废弃”，不属于当前运行路径；
4. 如旧开发说明与当前需求文档存在差异，以当前需求文档为准。特别是音频处理采用 FunASR 整段音频识别、短时签名 URL 与异步任务模式，不采用旧 ASR 的固定分片方案。

### 1.4 术语与缩略语

| 术语 | 含义 |
|---|---|
| JD | Job Description，岗位描述文本。 |
| ASR | Automatic Speech Recognition，自动语音识别。 |
| FunASR | 本系统当前用于非实时整段音频转写、句子时间戳和说话人识别的能力。 |
| LLM | 大语言模型，用于问答识别、量表生成、逐项覆盖判断与建议生成。 |
| 评分量表 | 针对单个问题生成的 5—8 个可验证评分要点及其权重、满分标准。 |
| 面经 | 用户选择公开发布的面试复盘内容。 |
| MVP | 最小可行产品，本说明书的交付范围。 |

## 2. 总体说明

### 2.1 产品定位

系统为 Web 形态的个人面试复盘平台。前端通过 REST API 调用后端；后端采用 Spring Boot 多模块架构，使用 MySQL 持久化业务数据、Redis 支撑验证码与 Token 黑名单，并按配置调用 ASR 与 LLM 能力。

### 2.2 用户角色

| 角色 | 说明 | 主要权限 |
|---|---|---|
| 游客 | 未登录访问者 | 浏览面经广场、面经详情、公开评论；访问有效分享链接。 |
| 普通用户（user） | 默认注册角色 | 管理本人资料、面试记录、笔记、收藏和分享；发布评论。 |
| 管理员（admin） | 系统管理角色 | 管理用户、AI 配置、公开面经和评论，查看系统统计及全部面试数据。 |

### 2.3 产品运行环境与技术约束

| 类别 | 已确认约束 |
|---|---|
| 后端 | Java 17 LTS、Spring Boot 3.5.15、Spring Security、MyBatis-Plus。 |
| 前端 | Vue 3、Vite、Element Plus、Pinia、Axios、ECharts。 |
| 数据与缓存 | MySQL 8.0+、Redis。 |
| 通信方式 | 基于 HTTP 的 REST API；文件上传使用 `multipart/form-data`；接口统一返回 JSON。 |
| 异步处理 | MVP 使用 Spring `@Async` 与自定义线程池；前端轮询处理状态。 |
| 文件存储 | MVP 使用本地存储，文件目录与应用分离并通过配置管理；后续可迁移 OSS。 |
| AI 能力 | 语音转写与文本分析评分均支持通过配置切换模型或提供商。 |

### 2.4 MVP 范围

**MVP 包含：**注册登录、面试上传与异步处理、FunASR 转写与角色映射、问答识别、统一量表评分、复盘详情、笔记、收藏、分享与面经广场、评论、AI 配置管理、RBAC 管理后台。

**MVP 不包含：**AI 模拟面试、历史趋势分析图表、多语言、PDF 报告导出、团队协作、在线录音、WebSocket 实时进度推送、按岗位分类的面试题库。

## 3. 外部接口需求

### 3.1 用户界面与页面

| 页面/路由 | 主要内容 |
|---|---|
| `/login`、`/register` | 邮箱验证码注册；邮箱或用户名登录。 |
| `/` | 本人面试记录列表、筛选与排序。 |
| `/resumes`、`/interview/upload` | 简历异步上传/选择，以及音频、JD 和面试信息提交。 |
| `/interview/:id` | 音频播放、转写、逐题评分、整体评分、建议、笔记和收藏。 |
| `/favorites` | 已收藏问题列表。 |
| `/experiences`、`/experiences/:id` | 公开面经广场、面经详情和评论。 |
| `/ai-config` | AI 模型配置管理。 |
| `/admin` | 用户管理、系统统计、面经与评论管理。 |

复盘详情页必须支持音频播放/暂停、进度拖拽、倍速播放和按问题时间戳跳转；转写文本应展示说话人角色，并能与问题高亮和音频位置联动。

### 3.2 外部服务接口

| 接口对象 | 输入/输出要求 |
|---|---|
| FunASR/ASR 服务 | 输入为模型支持格式的整段音频；输出至少含句子文本、原始 `speakerId`、开始时间和结束时间。 |
| LLM 服务 | 输入为带角色和时间戳的转写、问题、JD、简历事实背景及固定量表；输出为结构化问答、评分量表、覆盖状态、证据和建议。 |
| 邮箱验证码服务 | 支持向注册邮箱发送 6 位数字验证码。 |

### 3.3 后端 API 通用约定

1. 所有接口统一返回 `code`、`message`、`data` 三个字段。
2. 查询资源使用 GET，创建使用 POST，更新使用 PUT，删除使用 DELETE。
3. 需要登录的请求在 `Authorization` 请求头中携带 `Bearer {token}`。
4. 分页接口返回 `records`、`total`、`page`、`size`。
5. 公开访问接口限于面经广场、可见面经详情与公开评论查询；其余业务接口需认证。

## 4. 功能需求

以下优先级中，**P0** 表示 MVP 必须具备，**P1** 表示 MVP 应具备。

### 4.1 用户与认证（FR-AUTH）

| 编号 | 需求 | 优先级 | 验收条件 |
|---|---|---|---|
| FR-AUTH-01 | 系统应支持邮箱、用户名、密码和邮箱验证码注册。 | P0 | 合法验证码注册成功；用户名和邮箱重复时返回对应业务错误。 |
| FR-AUTH-02 | 验证码有效期为 5 分钟，同一邮箱 60 秒内仅可发送一次。 | P0 | 过期或错误验证码不可注册；60 秒内重复发送被拒绝。 |
| FR-AUTH-03 | 密码必须使用 BCrypt 加密存储，注册成功后自动登录。 | P0 | 数据库不保存明文密码；成功注册获得登录态。 |
| FR-AUTH-04 | 系统应支持邮箱或用户名加密码登录，并返回有效期 7 天的 JWT。 | P0 | 两种账号标识均可登录；响应包含 Bearer Token 与过期信息。 |
| FR-AUTH-05 | 用户退出登录时，服务端应将当前 Token 的 JTI 写入 Redis 黑名单，TTL 为该 Token 剩余有效期。 | P0 | 使用已退出 Token 调用受保护接口被拒绝。 |
| FR-AUTH-06 | 用户可获取和更新本人基本信息，并可修改密码。 | P1 | 未登录不能访问；用户只能修改本人资料。 |
| FR-AUTH-07 | 连续登录失败 5 次后，账户应锁定 15 分钟。 | P0 | 第 6 次登录返回登录受限提示。 |

### 4.2 面试上传、处理与记录（FR-INT）

| 编号 | 需求 | 优先级 | 验收条件 |
|---|---|---|---|
| FR-INT-01 | 用户先独立上传 PDF 简历并等待异步解析成功，再以有效 `resumeId`、MP3/WAV 面试录音和非空 JD 创建面试。 | P0 | 简历属于当前用户、未隐藏、状态为 `SUCCESS` 且正文非空；缺少任一必填项不可创建面试。 |
| FR-INT-02 | 音频最大 2GB、最长 2 小时；服务端通过 ffprobe 验证真实 MP3/WAV 格式与时长。 | P0 | 伪造扩展名、不支持类型、超限文件或超时长均返回明确错误。 |
| FR-INT-03 | 岗位名称和面试类型必填，公司、行业和标题选填；默认标题为“公司-岗位-日期”或“岗位-日期”。 | P1 | 支持 `coding`、`behavioral`、`system_design`、`comprehensive`，创建后除标题外元数据不可修改。 |
| FR-INT-04 | 上传成功后系统应创建 `PROCESSING` 状态记录，并以异步方式执行处理。 | P0 | 上传接口不等待完整 AI 分析；记录可查询到处理中状态。 |
| FR-INT-05 | 处理按“转写与角色映射→标准生成与逐项比对→服务端计分保存→整体评分与总结”四步执行。 | P0 | 状态接口返回当前步骤名、步骤编号与进度百分比。 |
| FR-INT-06 | 前端应通过 `GET /interviews/{id}/status` 轮询进度。 | P0 | 处理中可获得步骤和进度；完成或失败后返回最终状态。 |
| FR-INT-07 | 处理失败或取消时保留已完成阶段并允许重试；已完成面试使用独立重评。 | P0 | `retry` 仅接受 `FAILED/CANCELLED`；`reanalyze` 仅重做问答识别和评分，不调用 ASR。 |
| FR-INT-08 | 用户可分页查询本人面试记录，按公司、职位、行业、面试类型筛选，按评分或创建时间排序。 | P0 | 列表显示标题、公司、职位、状态、整体评分和创建时间。 |
| FR-INT-09 | 用户可删除本人面试记录，删除采用逻辑删除，并级联逻辑删除其问题记录。 | P0 | 删除后常规列表不可见；其他用户不得删除该记录。 |

### 4.3 转写、问答识别与评分（FR-AI）

| 编号 | 需求 | 优先级 | 验收条件 |
|---|---|---|---|
| FR-AI-01 | 系统应使用 FunASR 非实时识别整段音频，保存句子级 `text`、`speakerId`、`speakerRole`、`startTime`、`endTime`。 | P0 | 转写结果不是仅含纯文本；任一句可追溯至说话人与时间区间。 |
| FR-AI-02 | 系统应按问答语义、发言顺序和上下文，将原始说话人标识映射为“面试官”或“候选人”，并在同一场面试中保持一致。 | P0 | 转写页面显示业务角色，同时保留原始 `speakerId` 用于追溯。 |
| FR-AI-03 | ASR 不可用、结果为空或时间戳缺失时，系统应记录失败原因并允许重试，不得丢弃时间戳后静默完成。 | P0 | 触发该异常时记录为失败，而非产生不完整成功结果。 |
| FR-AI-04 | 系统应从完整对话中识别问答对，输出连续题号、问题、回答、说话人、时间范围和置信度。 | P0 | 结构化结果通过校验；题号连续且无重复问题。 |
| FR-AI-05 | 问答起止时间必须由 FunASR 原始句子时间戳计算，LLM 不得猜测时间。 | P0 | 任一问题时间范围能映射回原始句子时间戳。 |
| FR-AI-06 | 对每道识别问题，系统应在不查看候选人回答的前提下，结合问题、岗位、行业、企业等级、JD 与简历事实背景，独立生成标准满分回答和评分量表。 | P0 | 生成流程与回答比对分离；标准满分回答不因候选人既有经历降低要求。 |
| FR-AI-07 | 单题量表应含 5—8 个可验证要点，覆盖内容质量、逻辑性、表达能力、专业度四维度；权重均为正整数且总和为 100。 | P0 | 校验每道题四维度均出现、要点数合规、权重和为 100。 |
| FR-AI-08 | 候选人回答应仅与固定量表逐项比对，AI 不得修改要点、权重和满分标准。 | P0 | 比对输入和输出中的量表版本一致。 |
| FR-AI-09 | 每个要点的覆盖状态仅可为 `FULLY_COVERED`、`MOSTLY_COVERED`、`PARTIALLY_COVERED`、`MISSING`、`INCORRECT`、`NOT_APPLICABLE`。 | P0 | 不接受未定义状态。 |
| FR-AI-10 | 除 `MISSING` 和 `NOT_APPLICABLE` 外，逐项结果必须给出可在候选人原文逐字匹配的证据，并给出缺失点、错误点和改进方法。 | P0 | 证据无法在回答原文中匹配时，结构化结果校验失败。 |
| FR-AI-11 | 系统应由服务端计算单题分数：完全覆盖 1.0、基本覆盖 0.75、部分覆盖 0.5、缺失/错误 0，不适用项不进入分母；结果范围为 0—100 并四舍五入。 | P0 | 以已知量表和状态输入可复现相同得分。 |
| FR-AI-12 | 系统应保存标准满分回答、量表、覆盖状态、证据、缺失点、错误点、改进方法和维度得分至 `rubric_detail`。 | P0 | 复盘详情可查看评分依据。 |
| FR-AI-13 | 整体评分应汇总有效问题的四项维度均值，沟通协作由整场互动生成 0—100 分；总分由服务端按内容 25%、逻辑 20%、表达 15%、专业 25%、沟通 15%计算。 | P0 | 以维度输入可按固定权重复算总分。 |
| FR-AI-14 | AI 输出应通过 JSON、题号、权重、维度、状态和证据一致性校验；校验或重试后仍失败时，本次面试应标记失败。 | P0 | 无效结构化响应不会进入已完成状态。 |

### 4.4 复盘展示、笔记与收藏（FR-REVIEW）

| 编号 | 需求 | 优先级 | 验收条件 |
|---|---|---|---|
| FR-REVIEW-01 | 复盘详情应展示面试信息、音频播放器、完整转写、逐题评分、维度雷达图、综合得分、优势、不足和整体建议。 | P0 | 已完成记录可完整展示上述结果。 |
| FR-REVIEW-02 | 每个问题卡片应展示问题、候选人回答、0—100 分、维度分数、量表要点、覆盖状态、证据、缺失/错误点、改进方法和标准满分回答。 | P0 | 用户可追溯每题评分依据。 |
| FR-REVIEW-03 | 用户可对整场面试保存一条富文本复盘笔记；重复保存时覆盖更新。 | P1 | 同一用户、同一面试只保留一条面试笔记。 |
| FR-REVIEW-04 | 用户可对同场不同问题分别保存问题笔记；唯一范围为“用户+面试+问题”，同一问题重复保存时覆盖。 | P1 | 不同问题笔记互不覆盖。 |
| FR-REVIEW-05 | 用户可收藏问题并填写备注；收藏列表支持分页、按来源面试和评分筛选及按评分排序。 | P1 | 重复收藏返回相应业务错误；可取消收藏。 |

### 4.5 面经发布与评论（FR-EXPERIENCE）

| 编号 | 需求 | 优先级 | 验收条件 |
|---|---|---|---|
| FR-EXP-01 | 每场已完成面试最多发布一篇公开面经，使用数字 ID；发布者可填写最多 10,000 字 Markdown 总结。 | P1 | 重复发布复用同一记录；未完成面试不能发布。 |
| FR-EXP-02 | 发布者可撤回并重新发布；管理员下架后发布者不能自行恢复，只能由管理员解除限制。 | P0 | 用户状态与管理员治理状态分别保存，管理员锁定不可被用户覆盖。 |
| FR-EXP-03 | 面经公开题目、分数、关键差距、改进建议和标准答案，不公开回答、完整转写、音频、简历及私人笔记。 | P0 | 公开 DTO 中不含上述隐私字段。 |
| FR-EXP-04 | 面试删除或发起重评时自动撤回面经；恢复或重评完成后不自动重新发布。 | P0 | 评论随不可见面经隐藏但保留，重新发布/解除下架后恢复显示。 |
| FR-EXP-05 | 评论只能发布到当前可见面经，内容不超过 500 字。 | P1 | 面经撤回或下架时禁止新增评论。 |

### 4.6 AI 配置与管理后台（FR-ADMIN）

| 编号 | 需求 | 优先级 | 验收条件 |
|---|---|---|---|
| FR-ADMIN-01 | 管理员可新增、查看、更新、删除和设定默认 AI 配置。配置包含提供商、模型名、API Key、端点、用途和状态。 | P1 | 普通用户不可访问；同一提供商和用途下只能有一个默认配置。 |
| FR-ADMIN-02 | 系统应区分 ASR 与文本分析评分两种 AI 配置用途。 | P1 | 配置可分别用于语音转文字与 LLM 分析评分。 |
| FR-ADMIN-03 | 系统预置 `admin` 与 `user` 两个系统角色，并采用可扩展的用户—角色—权限 RBAC 模型；角色组织权限，接口以权限码授权，未明确授权则拒绝。 | P0 | 权限只从 `user_role -> role_permission -> permission` 关系计算；不存在按角色名或 `/admin/**` 路径自动放行。 |
| FR-ADMIN-04 | 管理员可分页查看、筛选、禁用/启用用户并分配预置角色；管理员账号同时关联 `user` 和 `admin`，权限取并集。 | P1 | 被禁用用户无法登录；禁止修改自己的角色、越权授权和产生无角色账号；最后一个有效权限管理者不能被禁用或撤权。 |
| FR-ADMIN-05 | 管理员可查看总用户数、今日新增用户数、总面试数、今日新增面试数、处理状态分布和平均评分。 | P1 | 统计接口返回上述指标。 |
| FR-ADMIN-06 | 管理员可管理公开面经与评论；下架面经不在广场显示，但原分享链接仍可访问并标识为已下架。 | P1 | 下架后广场不可见，分享链接行为符合约束。 |
| FR-ADMIN-07 | 系统应记录角色分配、账号状态、AI 配置及管理内容操作的权限审计日志。 | P0 | 具备 `audit:read` 权限的账号可查询日志；日志不保存密码、API Key 等敏感明文。 |

## 5. 数据需求与业务规则

### 5.1 核心数据对象

| 数据对象 | 主要内容 | 关键关系/约束 |
|---|---|---|
| 用户 | 账号、邮箱、密码、昵称、状态 | 用户名与邮箱唯一；密码 BCrypt 存储；用户表不保存角色字段。 |
| 面试记录 | 面试元数据、文件路径、JD、简历文本、转写、评分、处理状态和错误信息 | 一个用户对应多条面试记录。 |
| 面试问题 | 问答、时间范围、单题评分、维度分、参考答案、量表明细 | 一条面试对应多道问题。 |
| 面试笔记 | 面试笔记或问题笔记、用户、问题标识 | 面试笔记为一对一；问题笔记以用户、面试、问题为唯一范围。 |
| 收藏 | 用户、面试、问题和备注 | 用户可收藏多个问题。 |
| 面经 | 面试、发布者、Markdown 总结、发布状态、治理状态、发布时间、浏览量 | `interview_id` 唯一；一场面试最多一篇。 |
| 评论 | 面经、评论者、纯文本内容 | 评论长度不超过 500 字；仅可见面经可新增。 |
| AI 配置 | 提供商、模型、加密 API Key、端点、用途、默认标识 | 同一 provider + config_type 至多一个默认配置。 |
| 角色 | 角色编码、名称、系统内置标识和状态 | 当前预置 `user`、`admin`，允许后续扩展；角色本身不直接作为接口放行条件。 |
| 用户角色 | 用户、角色、关联时间 | 一个账号可关联多个角色；新注册账号自动关联 `user`；有效账号不得无角色。 |
| 权限与角色权限 | 稳定权限码、权限名称、角色权限映射 | 功能授权以 `role_permission` 显式配置为唯一来源；新增权限默认不授予任何角色。 |
| 权限审计日志 | 操作人、操作类型、目标、变更前后数据、来源 IP、结果和时间 | 记录授权和高风险管理操作；敏感字段必须脱敏或不记录。 |

### 5.2 数据完整性与生命周期

1. 所有表使用 BIGINT 自增主键；业务关联由应用层维护，数据库不建立外键，以便后续分库分表。
2. 所有业务表支持逻辑删除；删除面试记录时同时逻辑删除其问题记录。
3. 面试处理状态为 `PROCESSING`、`COMPLETED`、`FAILED`、`CANCELLED`；处理阶段保留转写、问答识别和评分产物并支持接续重试。
4. `transcript_segments` 应保存包含说话人和毫秒级时间戳的句子级 JSON，`rubric_detail` 应保存量表与逐项比对结果 JSON。
5. 用户只能访问本人的面试数据；管理员按权限可查看全部数据。
6. 角色和权限的唯一数据来源为 `role`、`user_role`、`permission`、`role_permission`；不得回退读取历史 `user.role` 字段。
7. 最后管理者按有效账号是否实际拥有 `user:role:assign` 权限判断，检查与变更必须在同一事务中完成并进行并发控制。

### 5.3 评分业务规则

1. 标准满分回答与量表先生成，候选人回答后比对；两阶段不得互相篡改评分基准。
2. 开放式问题允许多种合理回答达到满分，标准满分回答不等同于唯一措辞。
3. 相同问题在岗位、行业、企业等级和量表版本一致时，可复用已保存的标准满分回答和量表。
4. `NOT_APPLICABLE` 项不参与单题分母；其余有效要点按权重和覆盖系数计算。
5. AI 负责输出覆盖分类、原文证据和改进信息；最终题分和总分由服务端按固定公式计算。

## 6. 非功能需求

### 6.1 安全性（NFR-SEC）

| 编号 | 要求 |
|---|---|
| NFR-SEC-01 | 密码使用 BCrypt（salt rounds=10）存储；API Key 使用 AES-256-GCM 加密存储，每条密文使用独立随机 IV。 |
| NFR-SEC-02 | JWT 有效期为 7 天，退出时通过 Redis 黑名单失效；受保护接口必须校验 Token。 |
| NFR-SEC-03 | 所有非公开业务接口必须统一完成身份认证和授权决策；接口使用权限码进行功能授权，业务服务继续校验资源归属和状态，未明确授权则拒绝。 |
| NFR-SEC-04 | 使用 Jakarta Validation 校验参数，MyBatis-Plus 参数化查询防 SQL 注入，前端输入过滤并设置后端响应头防 XSS。 |
| NFR-SEC-05 | 上传文件须校验类型、大小；文件名使用 UUID 加原扩展名，存储路径与应用分离以避免路径遍历。 |
| NFR-SEC-06 | 密码、API Key 等敏感信息不得写入日志；密钥应通过环境变量或配置中心提供，不提交代码仓库。 |

### 6.2 可靠性与可恢复性（NFR-REL）

| 编号 | 要求 |
|---|---|
| NFR-REL-01 | AI 调用超时、网络异常或结构化响应校验失败时，应按已配置策略重试；最终失败须记录原因并将面试置为失败状态。 |
| NFR-REL-02 | LLM 输出须进行 JSON 清理、解析和必要修复；题号、权重、维度、覆盖状态和证据须通过一致性校验。 |
| NFR-REL-03 | 用户应可对失败记录重新处理；处理过程不得因缺失时间戳而以不完整结果标记成功。 |
| NFR-REL-04 | 上传后的耗时处理应异步执行，避免阻塞上传请求；前端可通过状态轮询获知处理结果。 |

### 6.3 性能与容量（NFR-PERF）

1. 系统应接受最大 2GB、最长 2 小时的 MP3/WAV 音频；PDF 简历通过独立接口上传并异步解析。
2. MVP 异步线程池配置为核心线程数 4、最大线程数 8、队列容量 100；该配置可通过环境调整。
3. 面试、问题、笔记、评论等列表接口均应采用分页返回。
4. 项目材料未定义页面响应时间、并发用户数、整体处理时长等量化服务等级指标，实施验收不得自行宣称未经测量的性能数值。

### 6.4 可用性、兼容性与可维护性（NFR-USE）

1. 系统应使用清晰的处理步骤、进度百分比、失败原因和业务错误码提示用户当前状态。
2. 评分结果须可追溯至量表、覆盖状态与回答原文证据；音频、转写、问题应通过时间戳联动。
3. 前后端采用 REST、统一响应和分页格式，便于独立开发与联调。
4. 后端采用 `ai-common`、`ai-auth`、`ai-interview`、`ai-ai`、`ai-web` 多模块分层；AI 客户端采用可配置工厂/策略模式，支持后续增加模型。
5. 可通过多环境配置区分开发、测试和生产环境。

## 7. 验收与测试要求

### 7.1 最小验收流程

1. **认证流程：**发送验证码、注册、自动登录、退出登录、失效 Token 拦截、登录失败锁定。
2. **核心业务流程：**登录后上传合法音频、JD 和 PDF 简历；确认记录进入处理中；轮询步骤直至完成或失败。
3. **复盘结果：**确认转写含角色与句子时间戳；问题与回答可定位；量表要点数量、维度覆盖和权重满足规则；证据可在回答原文中匹配；服务端计算得分可复算。
4. **记录管理：**测试分页、筛选、排序、删除和失败重试，并验证用户数据隔离。
5. **辅助功能：**测试面试笔记、问题笔记、收藏、分享链接、公开面经和评论权限。
6. **后台管理：**测试管理员用户管理、统计、面经管理、评论管理和 AI 配置管理；普通用户访问管理员接口应失败。

### 7.2 异常与边界测试

| 场景 | 预期结果 |
|---|---|
| 音频真实格式错误、音频超 2GB/2 小时、简历非 PDF 或解析失败 | 请求被拒绝并返回相应错误码/提示。 |
| Token 无效、过期、已退出或用户被禁用 | 受保护接口拒绝访问。 |
| 分享链接不存在或已到期 | 不展示分享内容。 |
| ASR 不可用、空结果、时间戳缺失 | 处理失败并记录原因，用户可重试。 |
| LLM 返回非法 JSON、题号不连续、量表权重不为 100、证据无法匹配 | 触发校验/重试；最终仍无效则标记失败。 |
| 非本人访问面试、越权删评论或访问管理员接口 | 返回无权限结果。 |

## 8. 变更控制

1. 新增功能、删除功能或修改评分公式前，应先更新本说明书中的范围、功能编号、数据规则和验收条件。
2. 涉及音频处理、评分机制或隐私展示范围的变更，应同时核对需求文档、数据库设计和开发文档的一致性。
3. 未在本说明书 MVP 范围内的能力，应作为后续迭代需求管理，不得在本版本验收中作为必交功能。
